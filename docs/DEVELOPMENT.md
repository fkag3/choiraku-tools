
# 開発ガイド — ちょいラク工具箱

## 1. プロジェクトの目的

「ちょいラク工具箱」は、日常の小さな作業を簡単にする
日本語の無料Webツール集です。

主な方針：
- プログラミング初心者でも保守しやすい構成にする
- スマートフォンとPCの両方で使いやすくする
- できるだけブラウザ内で処理を完結させる
- ページの表示速度と使いやすさを重視する
- 広告や寄付による収益化を目指す
- ホスティングサービスと広告サービスの規約を守る

## 2. 技術方針

- HTML：ページの構造
- CSS：デザインとレイアウト
- JavaScript：ツールの機能
- GitHub：ソースコードと変更履歴の管理
- 公開先：商用利用条件を確認した静的ホスティング

フレームワークや外部ライブラリは、
必要性を説明したうえで導入する。

サーバーやデータベースを必要としない機能は、
ブラウザ内で実装する。

## 3. Gitの運用ルール

### mainブランチ

- 安定版のコードを管理する
- 原則として直接編集しない
- 作業ブランチからPull Requestを通して変更する

### ブランチ名

- feature/機能名：新機能
- fix/修正内容：バグ修正
- design/変更内容：デザイン変更
- docs/変更内容：文書の変更
- chore/変更内容：設定・保守作業

例：
feature/character-counter
fix/line-count
docs/privacy-policy

### コミットメッセージ

次の形式を使用する。

- feat: 新機能の追加
- fix: 不具合の修正
- style: 見た目の変更
- docs: 文書の変更
- refactor: コードの整理
- chore: 設定や保守

例：
feat: add character counter
fix: correct line counting
docs: update development guide

## 4. コーディングルール

- 変数名や関数名は、意味が分かる名前にする
- 同じ処理を不必要に重複させない
- HTMLの見出しは適切な順序で使う
- ボタンや入力欄には、分かりやすいラベルを付ける
- キーボードでも操作できるようにする
- スマートフォンの画面幅でも正しく表示する
- 不要な外部通信を追加しない
- 既存機能を壊す変更は避ける

## 5. 作業の進め方

1. 変更の目的を明確にする
2. 関連ファイルと既存コードを確認する
3. 変更対象のファイルを列挙する
4. 作業ブランチを作成する
5. 必要最小限の変更を行う
6. 動作確認を行う
7. 差分を確認する
8. Pull Requestを作成する
9. 問題がなければmainにマージする
10. 公開環境で最終確認する

一度に複数の無関係な機能を変更しない。

## 6. テスト方針

変更した機能について、最低限次を確認する。

- 通常の入力で正しく動く
- 空欄や境界値でも問題がない
- 日本語、改行、空白を正しく処理する
- PCとスマートフォンで操作できる
- ブラウザのコンソールに重大なエラーがない
- 既存の機能が引き続き動く

未実施のテストを実施済みと報告しない。

## 7. セキュリティとプライバシー

- パスワードやAPIキーをソースコードに保存しない
- 個人情報を必要以上に収集しない
- 利用者の入力内容を無断で外部送信しない
- 外部サービスや解析機能を追加するときは、
  データの扱いと必要な告知を確認する
- 広告タグを追加するときは広告サービスの規約を確認する

## 8. GPTへの開発依頼ルール

GPTは、変更を提案する前に既存のコードと
この開発ガイドを確認する。

回答には次を含める。

1. 変更の目的
2. 変更対象ファイル
3. 実装内容
4. テスト手順
5. 既存機能への影響
6. GitHubでの作業手順

コードを変更する場合は、既存機能への影響を説明する。
必要以上にファイル構成を変更しない。

## 9. 公開ルール

- mainへのマージ前に変更内容を確認する
- 公開先の利用規約を守る
- 広告サービスの審査・ポリシーを守る
- 公開後に主要機能を実際に操作して確認する
- 不具合があれば修正用ブランチを作成する
